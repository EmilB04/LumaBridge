> **Pre-release.** Motherboard and fan lighting comes back after Armoury Crate restarts its lighting service, every RAM stick lights up, and the Azoth stays steady by cable.

## Fixed

- **Black motherboard and fans:** Armoury Crate can start its lighting service again every
  few seconds (seen while an ASUS keyboard is connected by cable). Each time, the board's
  lights stopped following LumaBridge and stayed dark. LumaBridge now takes them back each
  time the hardware helper pauses that service.
- **Only some RAM sticks lit:** a stick that missed one check on the memory bus at start was
  left dark. Each stick is now checked a few times, and when fewer answer than Windows lists,
  every slot gets the colors. If the RAM's lighting controller doesn't answer at first,
  LumaBridge keeps trying for a minute.
- **Azoth lighting freezing by cable:** key colors were sent faster than the keyboard could
  take them, which locked its lighting until the cable was replugged. Each update now waits
  for the keyboard's answer. A stuck keyboard no longer fills the log with the same warning
  every 2 seconds.

## Changed

- **Hardware access needs an update:** Devices → Hardware access shows **Update** once
  (one administrator prompt). The RAM and motherboard fixes need it.

## Validation

- The x64 Windows app and the helper build, and portable tests pass, including the new
  RAM slot rules.
- Not yet verified on real hardware: the board and fans after an Armoury Crate restart, the
  RAM with all three sticks, and the Azoth over a long cable session.
