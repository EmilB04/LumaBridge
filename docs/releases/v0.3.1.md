> **Pre-release.** Every running game shows up in Auto mode, and the silent Armoury Crate
> hand-back is fixed.

## New

- **Auto mode lists every running game**, not only the ones sending lighting. Games are
  found by where they're installed (Steam, Epic, EA, Ubisoft, GOG, Xbox, Riot, Rockstar,
  Amazon, Battle.net) or because Windows lists them as games (Game Bar). Each one shows
  whether it does dynamic lighting:
  - **Dynamic lighting** (green): it's driving your lights right now.
  - **Supports dynamic lighting** (amber): it has sent lighting before, or loaded a
    lighting SDK, but isn't sending colors yet. Many games only start in a match.
  - **No dynamic lighting**: it doesn't use a lighting SDK LumaBridge understands. Your
    idle choice (your color, rainbow, off or Armoury Crate) stays on, and the sidebar
    says e.g. "Rocket League - no dynamic lighting - your color".
- Games that ever sent lighting are remembered, so they show as supported next time
  right away.
- LumaBridge never opens a game's memory when an anti-cheat (Easy Anti-Cheat, BattlEye,
  Vanguard, ...) is installed with it or running. For those games, support shows up
  once they send colors.

## Fixed

- **Hand-back still left the lights frozen.** The hand-back task looked for the device
  named "AURA LED Controller" and restarted its *parent* device. On boards where that
  name belongs to the controller's USB device itself, the parent is a USB hub, so the
  task skipped it and nothing was restarted. The task now finds the controller by its
  USB id (`USB\VID_0B05&PID_1939\...` and the other Aura motherboard controllers), which
  is exactly what `pnputil /restart-device` restarts by hand.
  **Open Games → Armoury Crate hand-back and click Set up again** to update the task.
- The result of every hand-back now also appears in LumaBridge's own log (`lumabridge-app.log`, Settings →
  Open log folder), a few seconds after it runs.
