> **Pre-release.** RAM lighting works again when another tool has changed the sticks' ID chips, and Logitech mice and Aura can be lit without the vendor's software.

## New

- **Logitech mice without G HUB:** supported mice are lit directly over HID++ when G HUB is
  missing or its SDK can't start. The G502 X Plus keeps its per-LED effects; other
  compatible mice follow as one color. LumaBridge keeps looking for G HUB while it runs and
  uses it when it appears. Other Logitech gear can still use Windows Dynamic Lighting or
  OpenRGB.
- **Aura without ASUS's runtime:** if the Aura SDK can't connect, LumaBridge falls back to
  the direct USB connection.

## Changed

- **Memory lighting log:** the hardware helper's log lists each memory slot's ID chip
  (answers or silent, and its type byte), so a failure shows which slot is the problem.
- The Devices page and the Logitech card say whether the mouse is lit directly or through
  G HUB.
- **README and peripherals notes** describe lighting without vendor software.

## Fixed

- **RAM not lighting ("No DDR4 sticks answered on the SMBus"):** a stick's ID chip can be
  left on another page by another program, so its type byte reads 0 instead of DDR4. A
  stick now counts when its ID chip answers and isn't DDR3 or DDR5.
- **RAM never found when the SMBus was busy at start:** another program holding the bus
  for a moment left the memory unlit until the app restarted. The helper now tries again
  every 5 seconds.
- A Logitech mouse lit directly no longer switches off Windows Dynamic Lighting or OpenRGB
  for other Logitech devices.
